This work adds no experiment and changes no archived measurement. It extends the
independent audit with a shared parser contract, a separate acceptance-metrics
recount, three-way output reconciliation and a verified evidence manifest.
Member-authored parsers, report results and prior batches are not modified.

## 1. Parser contract

The live comparison parser and the archived summarizer were compared on 166
complete raw logs from the original comparison, the compatible comparison, the
four-thread follow-up and the independent member `account` batch.

For every complete log, the parsers agree on:

- schedule count;
- first failing schedule;
- buggy-schedule count;
- raw error-event count;
- completion status; and
- inner-timeout count.

A deterministic mutation matrix checks that both parsers fail closed for:

- duplicate end markers;
- events after completion;
- an end marker moved after the runner footer;
- duplicate error totals or round totals;
- over-budget schedule lines; and
- unattributed error events.

## 2. Independent acceptance-metrics recount

The new script parses the 30 comparison logs directly. It does not import the
repository summarizer. It requires one start marker, one end marker, ordered
footers, sequential schedules, sequential error-event numbers, one error event
per failing schedule, a 10,000-schedule budget, zero inner timeouts and a
successful runner footer.

For each of the ten case-method groups it recomputes:

- first failing position;
- explored schedules;
- buggy schedules;
- elapsed seconds; and
- arithmetic mean and sample standard deviation.

The script also independently reconstructs the five paired comparisons:
schedule reduction, serialized-minus-PERIOD elapsed time and the elapsed-time
ratio.

The recalculated values are compared with three archived outputs:

1. `summary.json`;
2. every comparison row in `all_trials.csv`; and
3. the method and paired tables in `SUMMARY.md`.

The acceptance denominators remain 30 complete comparison calls and 15
complete method pairs. This is a verification of existing evidence, not a new
sample.

## 3. Negative controls

Synthetic copies of the archive are changed one field or file at a time. The
audit must reject:

- a changed raw-log SHA-256;
- a changed raw metric in `records.json`;
- a changed mean in `summary.json`;
- a changed comparison value in `all_trials.csv`; and
- a changed row in `SUMMARY.md`.

These controls establish that agreement is not produced by comparing the same
source twice or by trusting one derived file.

## 4. Evidence provenance

The evidence manifest records repository-relative path, byte count and SHA-256
for the scripts, tests, this record and the retained command transcripts. The
checker rejects:

- a missing file;
- an extra or stale manifest path;
- duplicate paths;
- absolute or parent-traversing paths;
- symlinks;
- byte-count mismatches; and
- SHA-256 mismatches.

The manifest deliberately excludes itself to avoid a self-referential hash.
The manifest-check transcript is also excluded and records the result of
verifying the finalized manifest.

## 6. Limits

The 166-log parser comparison covers complete archived logs with the established
runner format. The mutation matrix is deterministic and targeted, not exhaustive
fuzzing.

The metrics recount verifies archived derivative outputs against raw logs. It
does not reinterpret the scientific protocol, establish cross-host equivalence
or replace the original acceptance receipt.

Raw runner elapsed times are stored to six decimal places while
`records.json` retains the full process timing. The elapsed-time comparison
therefore uses a one-microsecond tolerance; all count metrics remain exact.
