## 四、李扬烁：独立环境复跑

### 1. 准备与前置检查

使用干净的 x86_64 Linux 虚拟机或可独立重建的 Linux 环境；需要 Git、Bash、GNU `timeout`、Python 3.9 或更高版本、Make，以及可运行的 Docker。首次拉取源码和镜像需要网络。实验包装脚本使用特权容器，适合专门用于实验的环境；容器不挂载个人凭据。容器共用宿主机内核，因此必须记录宿主机系统和内核。

- [ ] 从公开仓库全新克隆，记录 `git rev-parse HEAD`；阅读 `README.md` 和 `experiments/2026-11-07/COMPARISON_PROTOCOL.md`。
- [ ] 记录本人执行日期、时区、CPU 架构、系统、内核、可用资源和 Docker 版本。
- [ ] 先执行以下检查；若失败，记录输出并处理具体失败原因，再进行实验。

```bash
uname -m
uname -a
docker version
git rev-parse HEAD
make check
make audit
```

`make audit` 核对仓库已有证据；本人的新批次仍需要按下面的要求单独复核。

### 2. 执行一个独立批次

在仓库根目录执行，保留新建的输出目录：

```bash
RUN_DIR="results/member-reruns/1240001156-account-$(date -u +%Y%m%dT%H%M%SZ)"
bash scripts/period_container_compatible.sh account "$RUN_DIR"
RUN_EXIT=$?
printf 'container return code: %s\n' "$RUN_EXIT"
cp docs/reviews/REVIEW_TEMPLATE.md docs/reviews/1240001156-clean-run.md
```

输出目录必须不存在；失败重试时使用新的时间戳目录，保留之前的失败记录。执行前记录所用协议版本，按该版本核对计划次数、方法标签和设置。当前对照使用 `period` 与 `author_serialized_abi16`，计划每种方法十次；是否完成、哪些记录可比较，要依据实际输出判断。`author_serialized_abi16` 对作者序列化驱动的共享内存接口作兼容修改，保留其调度枚举逻辑。原始 `author_serialized` 的驱动崩溃属于失败执行，不能解释为有效的“零错误”结果。上述复跑入口使用兼容版本。
