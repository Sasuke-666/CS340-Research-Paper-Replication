### 2. 执行一个独立批次

在仓库根目录执行，保留新建的输出目录：

```bash
RUN_STAMP=$(date -u +%Y%m%dT%H%M%SZ)
RUN_DIR="results/member-reruns/1240001156-account-$RUN_STAMP"
TRANSCRIPT_DIR="docs/reviews/evidence/1240001156-$RUN_STAMP"
mkdir -p "$TRANSCRIPT_DIR"
{
  date -Iseconds
  date -u -Iseconds
  git rev-parse HEAD
  uname -m
  uname -a
  cat /etc/os-release
  getconf _NPROCESSORS_ONLN
  free -h
  docker version
  python3 --version
} > "$TRANSCRIPT_DIR/host.txt" 2>&1
if bash scripts/period_container_compatible.sh account "$RUN_DIR" \
    > "$TRANSCRIPT_DIR/runner.txt" 2>&1; then
  RUN_EXIT=0
else
  RUN_EXIT=$?
fi
printf '%s\n' "$RUN_EXIT" > "$TRANSCRIPT_DIR/runner_exit_code.txt"
test -e docs/reviews/1240001156-clean-run.md || \
  cp docs/reviews/REVIEW_TEMPLATE.md docs/reviews/1240001156-clean-run.md
```

输出目录必须不存在；失败重试时使用新的时间戳目录，保留之前的失败记录。执行前记录所用协议版本，按该版本核对计划次数、方法标签和设置。当前对照使用 `period` 与 `author_serialized_abi16`，计划每种方法十次；是否完成、哪些记录可比较，要依据实际输出判断。`author_serialized_abi16` 对作者序列化驱动的共享内存接口作兼容修改，保留其调度枚举逻辑。原始 `author_serialized` 的驱动崩溃属于失败执行，不能解释为有效的“零错误”结果。上述复跑入口使用兼容版本。

本次只运行 `account`，两种方法各十次，共计划 20 次比较；现有五案例实验无需重复。旧批次中 `account` 两种方法均完成十次，见 [原有汇总](../results/2026-11-07/summaries/comparison-42381922637/SUMMARY.md)。本人应比较调度总数、首次发现、错误调度数和耗时；新环境结果无需强行与旧值相同。

若新批次已生成 `records.json`、`environment.json` 和 `manifest.json`，执行其专用汇总。必须显式给出单案例设计，输出放在原始批次之外；汇总器默认要求全部五个案例。

```bash

    --cases account --repeats 10 \
    --output "$TRANSCRIPT_DIR/account-summary" \
    > "$TRANSCRIPT_DIR/summary-check.txt" 2>&1; then

  SUMMARY_EXIT=$?

```

检查汇总中的 `integrity_ok`、实际分母、完整配对和全部未完成记录。完整批次的设计是 20 次尝试、两种方法各十次；最终完成数以实际结果为准。若在拉取镜像、构建或运行阶段提前失败，保留转录和缺项说明，再由本人定位并修复具体问题；失败记录本身不证明主实验已成功复现。按本人的实际日期重试时，保留全部旧目录。
