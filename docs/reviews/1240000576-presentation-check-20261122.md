## Recalculation against the published summary

Run from the repository root with Python 3. The standard-library script checks the six raw file digests, pairs each assertion marker with the preceding test ID, counts distinct failing IDs and checks the footers and indexed run status. It computes from the raw logs before comparing the results with the published table. The command completed with exit 0. [Recount script](../../scripts/recount_twostage_acceptance.py)

```sh
python scripts/recount_twostage_acceptance.py
```

Each cell uses three complete calls. All six detected an error, so the conditional first-failure statistic also uses three values per method. The mean is the sum divided by three. For the sample SD, sum the squared deviations from that mean, divide by two and take the square root. For example, the serialized first-failure mean is 37/3 and its sample SD is 25/√3 ≈ 14.4338. ## 中文讲解提要

本次贡献为“对组内新验收数据的独立复算与复核”。原始测量属于组内 11 月 22 日新宿主验收批次。

- 先说实验单位。11 月 15 日把同一个见证重放五次，五次都看到了指定断言。11 月 22 日做的是两种方法各三次完整搜索，每次搜索都枚举了 33 个调度。
- 解释数字时可以指向序列化第二份日志。第 29 个 `test` 后面第一次出现报错，所以这一次的首次失败位置是 29。把 4、29、4 求平均得到 12.3333，按分母 2 算样本标准差得到 14.4338。
- 解释缺陷时，先说明两次写入和两次读取各自分开加锁。读线程走到第 48 行，说明它保存的两个局部值是 1 和 0。日志能直接指出断言位置，具体抢占点仍然未知。
- 深度设为 3 时，双线程 twostage 的两种驱动都覆盖 2 至 4 个 period。换成三线程，序列化驱动会覆盖 3 至 5 个。新验收的 30 次比较、15 对和另计的 40 次诊断，均与原研究的 106 / 96 / 43 分开报告。
